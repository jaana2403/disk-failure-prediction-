# 💽 Disk Failure Prediction

Predict hard-drive failures from **SMART** sensor readings using machine learning.
This project tackles a realistic **predictive-maintenance** problem where failures
are rare (severe class imbalance) and the warning signals are weak and noisy — the
same challenge faced when working with real [Backblaze](https://www.backblaze.com/cloud-storage/resources/hard-drive-test-data)
drive-stats data.

## Highlights

- **End-to-end ML pipeline** — data loading, EDA, feature engineering, training, evaluation, and a live demo app.
- **Handles class imbalance** with `SMOTE` (applied to training folds only) plus `class_weight="balanced"`.
- **Leak-free design** — resampling and scaling live inside an [imbalanced-learn](https://imbalanced-learn.org/) pipeline, so the held-out test set is never contaminated.
- **Model comparison** — Logistic Regression baseline vs. Random Forest, keeping the best by ROC-AUC.
- **Runs instantly** — if no real CSV is present, a realistic *synthetic* SMART dataset is generated automatically.

## Results

Best model: **Random Forest** (ROC-AUC ≈ **0.89** on the held-out test set).

| Class          | Precision | Recall | F1    |
| -------------- | --------- | ------ | ----- |
| Healthy (0)    | 0.994     | 0.986  | 0.990 |
| **Failed (1)** | 0.514     | 0.713  | 0.597 |

> For predictive maintenance, **recall on the failure class** is the number that
> matters most — missing a failing drive (a false negative) is the costly error.
> A portion of failures are deliberately "silent" (no SMART warning), which caps
> achievable recall and mirrors the real-world limitation.

## SMART features used

| Attribute        | Meaning                              |
| ---------------- | ------------------------------------ |
| `smart_5_raw`    | Reallocated Sectors Count            |
| `smart_187_raw`  | Reported Uncorrectable Errors        |
| `smart_188_raw`  | Command Timeout Count                |
| `smart_197_raw`  | Current Pending Sector Count         |
| `smart_198_raw`  | Offline Uncorrectable Sector Count   |
| `smart_9_raw`    | Power-On Hours                       |
| `smart_194_raw`  | Temperature (°C)                     |
| `smart_193_raw`  | Load Cycle Count                     |

**Engineered features:** `total_error_count`, `sectors_per_hour`, `runs_hot`.

## Getting started

### 1. Set up the environment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. (Optional) Explore the data

```bash
python src/eda.py        # saves plots to reports/figures/
```

### 3. Train the model

```bash
python src/train.py      # compares models, saves the best to models/model.joblib
```

### 4. Evaluate

```bash
python src/evaluate.py   # prints metrics, saves confusion matrix + ROC curve
```

### 5. Launch the demo app

```bash
streamlit run app/streamlit_app.py
```

Then enter a drive's SMART readings and get a live failure-probability estimate.

## Using real data

To train on real Backblaze data instead of the synthetic set, download a
drive-stats CSV, save it as `data/raw/drive_stats.csv`, and re-run
`python src/train.py`. The loader picks it up automatically.
